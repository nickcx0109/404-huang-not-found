# 地圖與場景製作流程

這份文件規劃三章地圖要怎麼做，以及怎麼交給 Fable（claude-fable-5-2）去建模與擺場景。引擎延續網頁版 Three.js；模型以現成的 CC0 素材包為主，故事專屬的東西由 Fable 寫 Blender Python 腳本產生。

## 1. 做法一句話

**玩法資料和外觀分開。** 每一章先用一份關卡資料檔定好路線、碰撞、出怪點、補給點，用灰色方塊就能玩；之後 Fable 只換「看得到的東西」，不動碰撞和數值。這和 v0.5 `gfx/world.js` 的做法一樣（看不見的 `collider()` 加上看得見的模型），也方便在提案的架構圖裡說明：`LevelData → SceneBuilder → PropFactory`。

## 2. 風格：比上一版更陰森

上一版是「藍色月光的夜晚小鎮」，看得很清楚、偏乾淨。這一版改成「看不清楚、光源很少、顏色髒」。

| 項目 | v0.5（上一版） | 這一版 |
|---|---|---|
| 霧 | 藍灰，`FogExp2` 密度 0.0155，約 60 m 還看得到 | 灰綠，密度 0.035～0.05，**視距 20～30 m** |
| 曝光 | 1.25 | 0.8～0.95，暗部壓到幾乎全黑 |
| 主要光源 | 月光＋路燈 | **玩家手電筒**（每人一盞 SpotLight）＋少數場景光 |
| 飽和度 | 1.08 | 0.75～0.85，只留「重點色」是飽和的 |
| 重點色 | 無 | 每章一個，只用在要引導玩家注意的地方（見下表） |
| 動態 | 少 | 燈管閃爍、霧緩慢流動、遠處剪影、偶發閃電或警報燈旋轉 |
| 後製 | bloom、暗角、顆粒 | 加重暗角和顆粒，加一點色差；受傷時畫面變紅變窄 |

各章色票（實作時寫進 `art/style/palette.json`，程式只讀這個檔，不要寫死）：

| 章 | 場景 | 基調 | 重點色（引導用） | 氣氛元素 |
|---|---|---|---|---|
| 一、找車 | 起霧的山路、枯樹林 | 灰綠霧 `#2a3330`、近黑的樹 | 遠處車子的紅色尾燈 `#ff3b2f`，一路當方向指引 | 枯樹剪影、倒下的護欄、路邊廢車、霧裡偶爾閃過的人影 |
| 二、堅守陣地 | MVIDIA 總部大門前廣場 | 濕柏油的深藍灰 | 故障閃爍的公司綠色招牌 `#76ff3a`（自己設計的標誌，不要仿真實公司的 logo） | 旋轉的紅色警示燈、拒馬、翻倒的保全亭、門禁面板倒數 |
| 三、總部救人 | 停電的辦公大樓、機房、頂樓發射台 | 停電後的黑，紅色應急燈 | 燃料桶的橘黃 `#ffb020`（玩家要找的東西一定要亮） | 閃爍日光燈、機房的綠色 LED 牆、頂樓探照燈打在火箭上 |

原則：

1. 玩家要找的東西（車、燃料桶、出口）永遠比背景亮，陰森不能變成看不到路。
2. 每個鏡頭最多 1～2 個重點色。
3. 一個場景同時開著的動態燈 ≤ 8 盞（網頁效能），其餘用自發光材質假裝。
4. 殭屍在霧裡要先看到輪廓或眼睛反光，再看到細節。

## 3. 資料夾規劃

```
art/
  style/
    STYLE_GUIDE.md        風格規則（上一節的內容）
    palette.json          各章的霧、光、後製數值
    refs/                 已核可的參考截圖
  blender/                Fable 寫的 Blender 腳本，一個資產一支
    fuel_barrel.py
    mvidia_gate.py
    ...
  manifest.json           資產清單：id、來源、三角面上限、狀態
tools/art/
  build_assets.py         批次跑 art/blender/*.py → 輸出 GLB
  convert_kit.py          把素材包的 FBX 轉成 GLB、修縮放與材質
  preview.py              每個資產輸出 4 個角度的預覽圖
  check_assets.mjs        檢查面數、檔案大小、尺寸、命名
  shots.mjs               用 Playwright 在固定機位截場景圖
web/
  assets/models/          只放實際用到的 GLB
  levels/ch1.json         關卡資料：碰撞、路線、出怪點、補給、檢查點、機位
  levels/ch2.json
  levels/ch3.json
```

素材包的原始壓縮檔放在 repo 外（每個人自己下載到例如 `../asset_drop/`），repo 只收轉好、實際用到的 GLB。實際要貼給 Fable 的任務見 [FABLE_BUILD_PLAN.md](FABLE_BUILD_PLAN.md)。

## 4. 前置工作（人做，Fable 開工前）

1. 安裝 Blender 4.2 LTS（免安裝版也可以），確認 `blender --background --python-expr "print(1)"` 能跑。
2. 決定 `art/`、`tools/art/`、`web/levels/` 歸誰負責（建議：關卡資料跟流程同一人，美術資產另外分配）。
3. Three.js 固定 **0.128.0**，不要升級，以免改變既有光線與色彩。`index.html` 的 import map 指向 CDN 的 `build/three.module.js` 與同版本 `examples/jsm/`；類別用 `import` 取相依模組，GLB 使用 jsm `GLTFLoader`。只有一個 `js/main.js` 入口，不需打包。
4. 每一章開工前，Fable 跑出來的東西由該章負責人 review 再 commit，用自己的 GitHub 帳號。

## 5. 流程

### 第 0 步：氣氛樣板（最重要，先做）

在一個 30 m 長的灰色方塊小場景裡只調霧、光、後製，不做任何模型。輸出 3 組不同強度的截圖給大家選，選定的數值寫進 `palette.json`。

> 先把「陰森」定下來再做模型。模型做完才發現太亮或太暗，要全部重調。

完成條件：三人選定一組，截圖存進 `art/style/refs/`。

### 第 1 步：資產工具

做第 3 節的 `tools/art/` 四支工具。每個 GLB 的規格：

| 項目 | 上限 |
|---|---|
| 小道具（桶子、拒馬） | 1,500 三角面 |
| 大道具（車、保全亭） | 6,000 三角面 |
| 建築模組（牆、門、走廊一段） | 3,000 三角面 |
| 地標（總部大樓、火箭） | 20,000 三角面 |
| 貼圖 | ≤ 1024 px，能用頂點色就不用貼圖 |
| 單章總量 | ≤ 15 MB，按章載入 |

命名與方向：公尺為單位、+Y 朝上、正面朝 -Z、原點在底部中心。這些由 `check_assets.mjs` 檢查，不合格就不能 commit。

### 第 2 步：轉素材包

從素材資料夾挑要用的模型轉成 GLB：枯樹、岩石（Nature）、廢車與路障（ZombieEnvironment、ZombieVehicles）、室內家具（KenneyFurniture）。轉換時統一換成陰森色調的材質（降飽和、加髒污），讓不同來源看起來是同一套。授權記錄寫進 `art/CREDITS.md`。

### 第 3 步：故事專屬資產（Fable 寫 Blender 腳本）

每個資產走同一個循環：

```
規格卡（manifest.json 一筆）
  → Fable 寫 art/blender/<id>.py
  → build_assets.py 輸出 GLB
  → preview.py 輸出 4 張預覽圖
  → Fable 看預覽圖，對照規格卡自評，不合格回到腳本修改（最多 3 輪）
  → check_assets.mjs 通過
  → 人看預覽圖，核可後 commit
```

清單（依需要的章排序）：

| id | 章 | 說明 | 備註 |
|---|---|---|---|
| `road_segment_*` | 一 | 山路模組：直線、彎道、上下坡，含路肩與裂縫 | 接縫要能無縫拼 |
| `guardrail` / `guardrail_broken` | 一 | 護欄、撞壞的護欄 | |
| `escape_car` | 一 | 路盡頭的車，尾燈自發光 | 可先用 Quaternius 車改色 |
| `mvidia_gate` | 二 | 總部大門、門禁面板、保全亭 | 標誌自己設計 |
| `barricade_*` | 二 | 拒馬、沙包、警示燈 | |
| `office_kit_*` | 三 | 牆、門、窗、走廊、轉角、樓梯 | 2 m 格子對齊 |
| `server_rack` | 三 | 機房機櫃，LED 自發光 | |
| `freight_elevator` | 三 | 貨梯，含「3/10」顯示面板的位置 | |
| `fuel_barrel` / `_smoking` / `_wrecked` | 三 | 燃料桶三種狀態 | 一定要醒目 |
| `rocket` / `launch_pad` / `cage` | 三 | 頂樓火箭、發射台、關老黃的籠子 | |

角色（殭屍、Boss、老黃、主角）不在這次範圍，交給敵人與玩家模組另外處理。老黃做成一般的低多邊形人物就好，不要做出像真人的臉。

### 第 4 步：每章場景

每章分四輪，每輪一個 commit：

1. **灰盒**：只寫 `levels/chN.json`，用方塊擺出路線、碰撞、出怪點、補給點、檢查點。能從起點走到終點才算完成。
2. **擺模型**：照關卡資料把方塊換成模型，碰撞盒不動。
3. **打光與霧**：套用 `palette.json` 的該章數值，加閃爍燈、霧的流動、遠景剪影。
4. **截圖檢查**：`shots.mjs` 在關卡資料裡定好的 6～8 個機位截圖，Fable 對照風格規則自評，再給人看。

製作順序照提案的建議：第二章 → 第一章 → 第三章。

各章的場景重點：

- **第一章**：一條約 300 m 的路，分 3 段、2 個檢查點。兩旁用濃霧和樹牆擋住，不做真正的開放地形。路上隔一段距離就有一個「小景」（翻倒的車、空帳篷、掛在樹上的東西），讓玩家一直有東西可看。
- **第二章**：大門前約 40 × 40 m 的廣場，殭屍從 3 個方向進來，玩家背後是總部大門。掩體要讓三個人各守一邊。
- **第三章**：一樓（燃料桶散落區，約 20 個放置點）、貨梯、頂樓發射台三個區塊。室內用模組拼，燃料桶放置點寫在關卡資料裡，方便之後調整。

## 6. 交給 Fable 的方式

每一個步驟開一個 Fable 子任務，不要一次把整份文件丟給它。建議設定：模型 `claude-fable-5-2`，effort `high`，在獨立的 worktree 裡做，做完由負責人看過再合併。

任務說明的模板：

```
你在 404-huang-not-found repo 做地圖美術。先讀 docs/art/SCENE_PIPELINE.md 和 art/style/STYLE_GUIDE.md。

這次只做：<步驟名稱，例如「第 3 步：fuel_barrel 三種狀態」>
規格：<manifest.json 那一筆，或關卡資料的範圍>

規則：
- 不改碰撞、數值、遊戲邏輯；只改看得到的東西
- 每個資產或每一輪場景做完都要輸出預覽圖或截圖，自己看過再繼續
- check_assets.mjs 不過就不能算完成
- 每做完一件事 commit 一次，訊息用英文 Conventional Commits（feat(art): ...）
- 不要 push

完成時回報：做了什麼、預覽圖或截圖路徑、自評哪裡還不滿意、有沒有超出面數或大小。
```

## 7. 驗收

每一章算完成要同時符合：

- 灰盒版本能從起點走到終點，換上模型後一樣能走、碰撞位置沒變。
- 6～8 張機位截圖都由三人看過，至少兩人覺得「夠陰森又看得到路」。
- 在一般筆電上 1080p 維持 60 fps；做不到就先減燈、減霧的粒子，再減模型。預算與量測方式見 [PERFORMANCE_PLAN.md](../tech/PERFORMANCE_PLAN.md)。
- 該章資產總量在 15 MB 內，`check_assets.mjs` 全部通過。
