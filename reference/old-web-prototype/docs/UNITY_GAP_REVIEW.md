## 三、要先處理的架構問題

這些不先改，加新內容會越加越亂。

1. **商店寫死**：`TradingStation.Offers` 和 `Buy()` 用索引寫死 6 個商品。要改成一份用 ScriptableObject 存的商品清單，第 1、2、3、4、7 條都需要。
2. **玩家只能拿 3 把槍**：`PlayerController._owned = { true, false, false }` 和滾輪切換都寫死 3 格。需要一個 Loadout 或背包類別，管武器、各種子彈、投擲物、配件。
3. **抽獎只能做被動**：每個升級（`UpgradeEffect`）只有套用和移除。主動技能要加新的介面（`Activate()`、冷卻時間），再配上按鍵和 HUD。
4. **殭屍狀態用數字編號**：`ZombieActor` 用 `_special = 1…6` 加 if 判斷切換狀態。新增遠程怪、飛行怪前，要拆成各自的行為類別或行為樹節點。飛行怪還要另一套移動方式，因為現在都是貼地走，尋路（flow field）也只管地面。

## 四、為什麼畫面看起來粗糙

看過專案後，原因很具體：

- **全部是方塊**：地圖、超商、殭屍、槍，全都是 `OfflineTownSetup.cs` 用 `Box()` 拼出來的 Unity 立方體，沒有任何外部模型。`Art/CREDITS.md` 也寫明沒加任何模型或貼圖包。
- **材質只有純色**：沒有貼圖、法線貼圖、粗糙度變化，所以表面看起來是平的塑膠。
- **招牌字是舊版 `TextMesh`**：用 LegacyRuntime 字型，放大後會糊、有鋸齒。這是「像素感」的主要來源之一。
- **光照很平**：沒有環境光遮蔽（SSAO）、沒有烘焙光照、沒有反射探針（reflection probe），物體之間沒有陰影層次。
- **解析度不是問題**：URP 的 Render Scale 是 1、MSAA 4×，所以不是渲染解析度太低。

## 五、改善方案

### 先決定風格：建議走「風格化低多邊形」，不要硬拚寫實

| 路線 | 優點 | 缺點 |
|---|---|---|
| **風格化低多邊形**（推薦） | 素材包風格統一、效能好、三人小組做得完；加上好的光照會很像正式遊戲 | 不是照片級寫實 |
| 寫實 PBR | 最接近 3A 感 | 素材要很多且風格要一致，光照調整成本高；混用不同來源的素材會更醜 |

最重要的原則是**整個遊戲用同一個系列的素材**。混用兩三種風格，會比現在的方塊還突兀。

### 素材來源

授權每個都要確認，並記到 `Art/CREDITS.md`。

| 來源 | 內容 | 費用 / 授權 |
|---|---|---|
| Kenney（kenney.nl） | 城市、建築、道具、家具等低多邊形套件 | 免費，CC0 |
| Quaternius（quaternius.com） | 低多邊形角色、怪物、武器，很多附動畫 | 免費，CC0 |
| Mixamo | 人形角色與動畫，有殭屍走路、攻擊、死亡動畫 | 免費，需 Adobe 帳號 |
| Poly Haven / ambientCG | 寫實 PBR 貼圖（柏油、磚、混凝土）、HDRI、部分模型 | 免費，CC0 |
| Synty POLYGON 系列（如 Apocalypse、Town、City） | 一整套統一風格的城市、商店、殭屍、武器 | 付費；最省事、最像「正式遊戲」 |
| Unity Asset Store | 用 Free 篩選搜尋 convenience store / supermarket / zombie | 免費或付費，授權逐一看 |
| Sketchfab | 單一模型很多 | 授權不一，CC-BY 需署名 |

AI 生成 3D（如 Meshy、Tripo）可以補單一道具，但風格難統一、拓樸常常很亂，不建議拿來做主要場景或角色。

### 超商與地圖要「像一般遊戲」的具體做法

1. **超商**：外觀要有玻璃門窗、招牌燈箱、雨遮；室內要有貨架、冰櫃、收銀台、天花板燈。現在的交易站可以直接變成「收銀台」，抽獎機變成店裡的扭蛋機或夾娃娃機，玩法不用改。
2. **街道**：路緣石、人行道、斑馬線、路燈、廢棄車輛、垃圾桶、圍欄和路障。路障剛好就是第 1 條「花錢開拓區域」要用的道具。
3. **用貼花（Decal）增加細節**：URP 的 Decal 功能可以貼血跡、裂縫、油漬、道路標線，成本低、效果大。
4. **招牌改用 TextMeshPro**：字會變清晰；配合發光材質和 Bloom，就有霓虹燈效果。
5. **光照**（不用換任何模型也能先做，效果最明顯）：
   - Renderer 加上 SSAO
   - 靜態建築標 Static 並烘焙光照貼圖（lightmap），加光源探針（light probe）
   - 超商、路燈用暖色點光源，和夜空的冷色對比
   - 超商附近放反射探針，玻璃和地面的反光才會真實
   - 色調映射用 ACES，加一點霧和粒子霧氣
6. **殭屍**：換成有骨架的模型，配 Mixamo 或素材包附的動畫，用 Animator 取代現在 `Animate()` 手動擺手腳的做法。

### 套用到現有程式時要注意

- **場景是程式生成的**：`OfflineTownSetup.cs` 用程式產生整個場景。換模型時可以讓它改成擺 prefab，或改成手動擺好的場景，二選一，先由 C 決定。
- **爆頭判定靠名字**：靠的是名字叫 `Head` 的碰撞體。新的殭屍模型要在頭骨上掛一個叫 `Head` 的碰撞體，不然爆頭會失效。
- **碰撞和尋路**：碰撞體繼續用簡單的方塊或膠囊，不要直接用高面數網格。尋路（flow field）的障礙物也要跟著新場景更新。
- **大型素材要 Git LFS**：要改 `.gitattributes`，依規則需要使用者明確同意。
- **加套件**：加 ProBuilder 或其他套件會改到 `Packages/manifest.json`，同樣需要先同意。

### 建議順序

| 階段 | 內容 | 負責 | 預估 |
|---|---|---|---|
| 1 | 光照與後處理：SSAO、烘焙光、TextMeshPro 招牌、貼花 | C | 1–2 天 |
| 2 | 換環境：同一套素材的街道與超商（含室內） | C | 3–5 天 |
| 3 | 換殭屍模型與動畫，保留 `Head` 碰撞體 | B | 2–4 天 |
| 4 | 換第一人稱槍模型、加槍口火光和彈殼 | A | 2–3 天 |

第 1 階段做完，同一批方塊看起來就會差很多。可以先做這一步，確認方向再花錢買素材。
